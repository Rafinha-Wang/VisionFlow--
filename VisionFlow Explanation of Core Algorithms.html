VisionFlow 核心算法讲解

基于纯 C++ 的相机运动分析与视频稳像系统：从局部块匹配到全局仿射补偿，再到相机轨迹平滑与虚拟云台策略。

整体算法流程

VisionFlow 的核心思想是：先从相邻帧中估计相机运动，再过滤局部干扰，接着用仿射模型进行画面补偿，最后通过轨迹平滑和虚拟云台策略提升视频稳定感。

BMP / MP4 / VFVID → 统一成 BMP 帧序列 → 灰度化 → 块匹配 → RANSAC → 仿射估计 → 轨迹平滑 → 稳定输出 → MP4 / VFVID / 帧目录
局部层面 找出每个图像块在下一帧中的位移，得到大量局部运动线索。
全局层面 用 RANSAC 找出大部分背景区域都支持的统一相机运动。
时间层面 对多帧相机轨迹进行平滑，削弱高频抖动，保留主要运镜趋势。

1. 块匹配运动估计

块匹配的目标是估计相邻两帧之间的局部位移。它不是直接判断整张图移动了多少，而是把图像切成许多小块，分别寻找每个小块在下一帧中最相似的位置。

1.1 基本思路

当前帧小块 → 在下一帧附近搜索 → 计算相似度 → 得到 dx, dy

假设当前帧中有一个 32×32 的图像块，位置是 (x, y)。程序会在下一帧的附近区域内搜索，找到最像这个块的位置。如果最像的位置是 (x + 5, y - 2)，那么这个块的局部运动就是：

dx = 5, dy = -2

1.2 相似度如何计算

常见做法是使用 SAD，也就是绝对差求和：

SAD(dx, dy) = Σ | I1(x, y) - I2(x + dx, y + dy) |

SAD 越小，说明两个图像块越相似。程序会在搜索范围内找到 SAD 最小的位置，把它作为该图像块的匹配结果。

1.3 关键参数

参数 含义 对算法的影响
blockSize 每个匹配块的大小 越大越稳定，但细节不敏感；越小越灵敏，但更容易受噪声影响。
blockStep 相邻匹配块之间的间隔 越小匹配点越多，结果更稳定，但速度更慢。
searchRadius 每个块在下一帧中搜索的最大范围 越大越能处理大运镜，但也更慢、更容易误匹配。
sampleStride 块内部采样步长 越小越准确，越大越快。
textureThreshold 过滤低纹理图像块 避免天空、白墙等平坦区域造成错误匹配。

1.4 为什么需要块匹配

视频稳像的第一步是知道相机怎么动。块匹配提供了大量局部位移信息，这些信息后续会被 RANSAC 进一步筛选，最终估计出全局相机运动。

小结：块匹配用于从相邻帧中提取局部运动线索，为后续全局仿射运动估计提供匹配点基础。

2. RANSAC 异常匹配过滤

块匹配得到的局部位移并不全是可靠的。画面中的人物、车辆、光照变化、低纹理区域都会造成错误匹配。RANSAC 的作用就是从这些匹配点中找出最符合全局相机运动的一批点。

2.1 为什么需要 RANSAC

视频画面中不仅有相机运动，还有前景物体运动。例如人从画面中走过，块匹配会认为人所在区域发生了位移。但这个位移并不代表相机运动。

问题：如果直接使用所有匹配点，前景主体运动和错误匹配会干扰相机运动估计，导致稳像后画面抽动或漂移。

2.2 RANSAC 的基本流程

随机选少量匹配点 → 拟合运动模型 → 统计内点数量 → 重复多次 → 选择最佳模型

RANSAC 会反复随机选择少量匹配点，尝试拟合一个全局运动模型。然后检查其他匹配点是否也支持这个模型。如果某个点的预测误差小于阈值，就认为它是 内点 inlier；否则就是 外点 outlier。

error = distance( predicted_position, actual_matched_position )

如果：

error < ransacThreshold

那么这个匹配点就被视为内点。

2.3 内点和外点

内点 inliers

符合全局相机运动规律的匹配点，通常来自背景、建筑、地面等稳定区域。

外点 outliers

不符合全局相机运动的匹配点，可能来自前景主体、噪声、光照变化或错误匹配。

2.4 关键参数

参数 含义 影响
ransacIterations RANSAC 迭代次数 越大越稳，但速度更慢。
ransacThreshold 判断内点的误差阈值 越大越宽松，越小越严格。
inlierRatio 内点比例 反映当前运动估计是否可靠。
小结：RANSAC 用来过滤前景运动、错误匹配和噪声，只保留符合统一全局相机运动的可靠匹配点。

3. 仿射变换补偿

仿射变换补偿是 VisionFlow 实现稳像的核心步骤。它根据估计出的相机运动，对当前帧进行反向变换，使画面尽量对齐到稳定后的目标视角。

3.1 什么是仿射变换

仿射变换可以表示平移、旋转、缩放和轻微倾斜。它的数学形式是：

x' = a · x + b · y + tx
y' = c · x + d · y + ty

其中：

  • tx, ty 表示平移；
  • a, b, c, d 可以表示旋转、缩放和倾斜；
  • x, y 是原图像坐标；
  • x', y' 是变换后的图像坐标。

3.2 为什么不用简单平移

真实拍摄中的相机抖动不一定只是左右上下移动，还可能存在轻微旋转、缩放或透视变化。如果只使用简单的 dx, dy 平移，无法处理这些复杂情况。

简单平移

只能处理左右上下移动，适合非常简单的抖动。

仿射变换

可以同时表达平移、旋转、缩放，更适合真实手持视频。

3.3 补偿的核心思想

程序先估计原始相机轨迹，再生成一个更平滑的目标轨迹。每一帧需要执行的补偿量可以理解为：

correction = smooth_camera_path - original_camera_path

如果原始轨迹某一帧突然向右抖了一下，而平滑轨迹没有这个突然变化，那么程序就会对该帧施加一个反向补偿，把画面拉回目标位置。

3.4 裁剪与缩放

仿射补偿后，图像边缘可能出现空白区域。为了避免输出视频出现黑边，程序需要进行裁剪和缩放。

注意：稳像效果越强，通常需要的裁剪越大。因此 correctionStrength 和 maxCropRatio 需要平衡。

3.5 关键参数

参数 含义 影响
correctionStrength 稳像补偿强度 越大稳像越明显，但裁剪和拉扯风险更高。
maxCropRatio 最大裁剪比例 越大稳像空间越大，但画面损失更多。
borderPadding 安全边距 减少黑边，但会增加裁剪。
cropSafeCorrection 安全裁剪约束 避免补偿过强导致边缘异常。
小结：仿射补偿根据相机运动估计结果对图像进行反向变换，使当前帧对齐到平滑后的目标轨迹，从而达到视频稳像效果。

4. 相机轨迹平滑 + 虚拟云台策略

轨迹平滑和虚拟云台策略决定了输出视频的观感。VisionFlow 不只是逐帧对齐，而是把相机运动看成一条连续轨迹，再对轨迹进行平滑处理。

4.1 为什么要平滑轨迹

如果只让每一帧对齐上一帧，误差会不断累积，还可能产生新的抖动。正确做法是先得到整个视频的原始相机轨迹，再生成一条更平滑的目标轨迹。

原始相机轨迹 → 去除高频抖动 → 平滑目标轨迹 → 计算补偿量

这里的“高频抖动”可以理解为相机在短时间内突然来回跳动；而“低频趋势”则是用户真实想保留的运镜方向。

4.2 static 模式

static 模式适合固定机位或基本不运镜的视频。它的目标是尽量锁定初始视角，让画面更像三脚架固定拍摄。

static：尽量把目标轨迹拉回第一帧附近

核心参数是：

  • lockToOriginStrength：锁定第一帧视角的强度；
  • correctionStrength：补偿强度；
  • smoothRadius：轨迹平滑半径。

4.3 motion 模式与虚拟云台

motion 模式适合跟拍、平移、推拉等运镜视频。它不会强行把画面锁死，而是模拟虚拟云台效果：保留原始运镜的大方向，同时削弱高频抖动。

motion：保留大方向运镜，平滑短时间抖动

这类似大疆云台或运动相机电子防抖的观感：用户仍然能看到镜头在移动，但移动过程更顺滑、更稳定。

4.4 虚拟云台参数

参数 含义 影响
virtualGimbalEnabled 是否启用虚拟云台 motion 模式建议开启。
gimbalPositionStiffness 位置跟随强度 越大越跟手，越小越平滑。
gimbalPositionDamping 位置阻尼 越大运动越连续，但可能拖尾。
maxGimbalPositionSpeed 最大移动速度 决定能否跟上快速运镜。
maxGimbalPositionAccel 最大加速度 决定响应方向变化的速度。

4.5 static 与 motion 的区别

模式 目标 适合视频 错误使用的后果
static 尽量锁定第一帧视角 固定机位、小幅抖动 用于运镜视频时，会显得画面被强行拉住。
motion 保留运镜趋势，削弱抖动 跟拍、平移、推拉、走路镜头 用于固定镜头时，稳定效果可能不如 static 明显。
小结：VisionFlow 将相机运动看作时间序列轨迹，通过 static 和 motion 两套策略分别处理固定镜头与运镜镜头。motion 模式使用虚拟云台思想，在保留主要运镜趋势的同时削弱高频抖动。

5. VFVID 纯 C++ 原生视频容器

VFVID 是 VisionFlow 自定义的简易视频容器。它不是要替代 MP4，而是为项目提供一种不依赖 ffmpeg、OpenCV 或其他视频库的纯 C++ 帧序列存储方式，用于比赛展示、实验复现和批处理队列中的原生输入输出。

5.1 为什么需要 VFVID

MP4 是通用视频格式，体积小、播放方便，但解码和编码非常复杂。如果把 MP4 解码器直接集成进项目，通常需要引入 FFmpeg 这类大型第三方库。VisionFlow 的 MP4 支持采用外部 ffmpeg.exe 做格式转换，而 VFVID 则展示了另一条路线：

核心定位：VFVID 用 C++ 标准库直接读写图像帧数据，让项目在不依赖视频编解码库的情况下，也能拥有“视频文件”级别的输入输出能力。
BMP 帧目录 最基础、最稳妥，适合作为绝对合规的核心算法输入。
MP4 文件 用户友好，通过外部 ffmpeg.exe 转换格式，不参与核心算法。
VFVID 文件 VisionFlow 原生容器，纯 C++ 读写，体现工程完整性。

5.2 文件结构

VFVID 当前版本采用简单的二进制顺序存储结构。文件开头是固定头部，后面依次存放每一帧的 RGB24 原始像素数据。 

[VFVID Header]
magic       = "VFVID01"
width       = 图像宽度
height      = 图像高度
fps         = 帧率
frame_count = 帧数
channels    = 3
frame_bytes = width * height * 3

[Frame Data]
frame_0001 RGB24 pixels
frame_0002 RGB24 pixels
frame_0003 RGB24 pixels
...

由于每帧都是 RGB24 原始数据，VFVID 是无损的，但体积会比 MP4 大很多。这是有意设计的取舍：它追求结构简单、可解释、纯 C++ 易实现，而不是追求压缩率。

5.3 读写流程

BMP 帧目录 → 读取 RGB24 → 写入 VFVID 头部 → 连续写入帧数据
VFVID 文件 → 读取头部信息 → 逐帧读取 RGB24 → 还原 BMP 帧目录

5.4 在稳像管线中的位置

VisionFlow 的核心稳像算法仍然处理统一的 BMP 帧序列。VFVID 的作用是在算法前后做格式适配： 

输入 input.vfvid
        ↓ 纯 C++ 解包
临时 BMP 帧序列
        ↓ VisionFlow 核心稳像算法
稳定后的 BMP 帧序列
        ↓ 纯 C++ 打包
输出 output.vfvid

这样做的好处是：算法模块不需要关心输入来自 MP4、BMP 文件夹还是 VFVID；主程序只需要把不同输入统一转换为帧序列，再交给同一套运动估计和稳像流程。

5.5 支持的命令

命令 作用 说明
VisionFlow.exe --pack input_frames output.vfvid 30 打包 把 BMP 帧目录打包成 VFVID，最后一个参数是 FPS。
VisionFlow.exe --unpack input.vfvid output_frames 解包 把 VFVID 还原成 BMP 帧目录。
VisionFlow.exe --vfinfo input.vfvid 查看信息 显示宽度、高度、FPS、帧数、像素格式和数据大小。
VisionFlow.exe --mode auto input.vfvid output.vfvid 直接稳像 输入和输出都使用 VisionFlow 原生容器。

5.6 与批处理队列的关系

批处理队列可以混合使用 BMP、MP4 和 VFVID。例如： 

mode,input,output
auto,case1.mp4,output/case1.mp4
static,case2.vfvid,output/case2.vfvid
motion,case3_frames,output/case3_frames

这使 VisionFlow 形成三层输入输出能力：BMP 作为基础帧序列，MP4 面向普通用户，VFVID 面向纯 C++ 工程展示和实验数据管理。

注意：VFVID 当前版本没有压缩、索引表和随机访问能力，因此它更适合作为项目原生实验格式，而不是通用视频格式。

算法与工程模块之间的关系

块匹配、RANSAC、仿射补偿和虚拟云台共同组成核心稳像算法；VFVID 则位于算法外层，负责纯 C++ 视频帧序列管理。

步骤 输入 输出 作用
块匹配运动估计 相邻两帧灰度图 局部匹配点 获得图像块位移线索
RANSAC 过滤 局部匹配点 可靠内点 + 全局模型 过滤前景运动和错误匹配
仿射变换补偿 全局相机运动 补偿后的图像帧 把画面对齐到目标视角
轨迹平滑 + 虚拟云台 多帧相机轨迹 平滑目标轨迹 决定最终视频观感
VFVID 原生容器 BMP 帧序列或 VFVID 文件 VFVID 文件或 BMP 帧序列 提供纯 C++ 视频序列打包、解包和信息读取能力 
核心总结：
局部块匹配负责“找运动”；
RANSAC 负责“筛掉错误运动”；
仿射补偿负责“把画面拉回稳定位置”；
轨迹平滑和虚拟云台负责“让输出视频看起来顺”；
VFVID 负责“用纯 C++ 管理视频帧序列”。
